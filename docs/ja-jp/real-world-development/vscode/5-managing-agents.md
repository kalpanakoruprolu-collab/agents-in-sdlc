GitHub Copilot を agent mode で使うと、コードベースの調査、変更の提案、ファイルの編集、コマンドの実行などを自律的に行います。VS Code の Copilot Chat では、作業がローカルでリアルタイムに進むため、ツールの呼び出しやファイルの編集を逐一確認できます。差分をインラインでレビューし、変更ごとに承認または取り消しを行い、エディターを離れずに追加のプロンプトを送信して作業の調整や拡張ができます。

この演習では、次のことを行います。

- アクセシビリティエージェントの作業をリアルタイムで監視します。
- 提案されたファイルの編集をレビューして承認します。
- セッションの途中でエージェントに追加の指示を出し、ハイコントラストに加えてライトモードのトグルを追加します。

## シナリオ

[演習 4][previous-lesson]で使ったアクセシビリティカスタムエージェントは、ハイコントラストモードを実装しています。作業中にデザインチームから追加の依頼がありました。既定のテーマが暗すぎると感じる利用者のため、ライトモードのトグルも追加してほしいとのことです。最初から新しい会話を始める代わりに、現在のセッションに追加の指示を出して作業を広げます。

## Copilot の進捗を監視する

Copilot Chat ビューでは、エージェントが実行する各手順を確認できます。調べたファイル、実行したコマンド、提案された編集が表示されます。ファイルの編集は差分と **Keep** / **Undo** の操作とともにチャットに表示されます。

1. 演習 4 で使った Copilot Chat ビューに戻ります。
2. エージェントの作業中は、チャットをスクロールしてツールの呼び出しを確認します。ファイルの読み取りと編集、エージェントが実行を求めるターミナルコマンドが表示されます。
3. エージェントがファイルの編集を提案すると、差分がインラインで表示されます。
    - 変更を承認するには **Keep** を選択します。
    - 変更を取り消してエージェントに再度作業させるには **Undo** を選択します。
4. チャットの上部にある **Files changed** を開くと、セッション中にエージェントが変更したファイル全体を確認できます。

> [!NOTE]
> ターミナルコマンドの実行などで許可が必要な場合、エージェントは一時停止して **Allow** を表示します。内容を確認し、実行してもよいコマンドだけを許可してください。

5. エージェントがハイコントラストモードの実装を完了するまで待ちます。最後に、変更内容を要約するメッセージが表示されます。

## エージェントにライトモードの追加を依頼する

ハイコントラストモードが実装されたので、同じ会話を続けてライトモードのトグルを追加します。同じチャットセッションを続けることで、エージェントは以前の作業から得たコンテキスト、つまり変更したコンポーネント、スタイルの方針、設定を保存するローカルストレージのパターンを維持できます。

1. Copilot Chat の入力欄に次の追加プロンプトを送信します。

    ```plaintext
    よいですね。ハイコントラストのトグルに加えて、ライトモードのトグルも追加してください。同じ方法でローカルストレージに設定を保存し、ユーザーインターフェイス (UI) の同じ領域から利用できるようにしてください。ハイコントラストとライトモードは、それぞれ独立して有効にできるようにしてください。
    ```

2. エージェントが前の変更を確認し、ライトモードの追加を提案します。
3. ハイコントラストモードのときと同じように、新しい編集を確認します。差分ごとに **Keep** または **Undo** を選択します。
4. エージェントの方向性が希望と異なる場合 (たとえばトグル UI を好まない方法でリファクタリングする場合) は、チャット入力欄の横にある **Stop** ボタンで作業を停止し、説明を補うメッセージを送信できます。

> [!TIP]
> 進行中のセッションを方向づける方が、最初からやり直すよりも迅速です。追加のプロンプトで調整 ("CSS を簡素化し、セレクターの重複ではなく CSS 変数を使ってください")、修正 ("3 つ目のトグルを追加せず、既存の設定パネルにライトモードを組み込んでください")、範囲の拡張 ("両方のトグルにキーボードショートカットも追加してください") を依頼できます。

## 作業ファイルをレビューする

変更をコミットする前に、エージェントが編集した内容を確認します。

1. VS Code で **Source Control** ビューを開きます。
2. 変更されたファイルの一覧を確認します。Astro コンポーネント、スタイル、関連テストなどが更新されているはずです。
3. 変更されたファイルをいくつか開き、差分を確認します。アクセシビリティカスタムエージェントが示したパターン、つまり Accessible Rich Internet Applications (ARIA) 属性、キーボード操作、セマンティック HTML、ローカルストレージによる設定保持が反映されていることを確認します。
4. 問題がなければ、Source Control パネルで変更をステージしてコミットします。次の[レッスン][next-lesson]で公開します。

## まとめと次のステップ

Copilot Chat の agent mode を使い、進行中のセッションを監視して方向づけました。ファイルの編集を確認しながら承認または取り消し、コンテキストを保ったまま追加のプロンプトを送信して作業を広げました。

このレッスンでは、次のことを行いました。

- エージェントの作業をリアルタイムで監視しました。
- 個々のファイル編集を承認または取り消しました。
- 追加のプロンプトを使って、進行中のセッションの方向を調整しました。

[次のレッスン][next-lesson]では、アクセシビリティ作業をプルリクエストとして公開し、このラボでローカルのカスタムエージェントが行った変更をレビューします。
